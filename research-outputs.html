Research Outputs

Previously unknown bugs I have found in open-source RISC-V processors and reported upstream. Every count is a public GitHub or GitLab issue with a reproducible test case. Counts as of November 2026.

264bug reports filed
23processor cores
31confirmed by maintainers

Paper under review

LLM-guided formal verification for RISC-V security, submitted to the IEEE Symposium on Security and Privacy (S&P) 2027.

Bugs by processor

The cores range from embedded microcontrollers to Linux-capable, superscalar, and out-of-order designs, including Tenstorrent's Ocelot, XiangShan, CVA6, OpenC910, and VeeR-EL2.

How the bugs were found

The bugs come from three efforts: an LLM-guided formal verification framework (101 bugs), RVSentry, a reusable library of formal security checks for RISC-V cores (126), and an extended version of the ACT4 architecture test suite (37).

What kind of bugs

Most of the RVSentry and ACT4 findings are in control and status registers, trap and interrupt handling, and memory protection, the logic that keeps privilege levels and processes apart.

Selected findings with security impact

  • Memory isolationOcelot
    Vector loads and stores skip physical memory protection (PMP) checks entirely. Issue #21 · Awaiting response
  • Memory isolationCVA6
    A page-walk result lands in the wrong TLB, so an execute-only page becomes readable and a non-executable page becomes executable. Issue #3757 · Awaiting response
  • Memory isolationSargantana
    The TLBs ignore the address-space ID, so one process can reuse another's translations after a context switch. Issue #153 · Confirmed by maintainers
  • Memory isolationBOOM
    A page-table walk that overlaps a TLB flush is still installed, so loads keep using the old mapping. Issue #830 · Awaiting response
  • Memory isolationOpenC910
    A walk started in the old address space is installed under the new one's ID after a context switch. Issue #86 · Awaiting response
  • Memory isolationXiangShan
    When two data-TLB entries match, the core returns the bitwise OR of their physical pages and permissions. Issue #6809 · In discussion with maintainers
  • Memory isolationShakti C-Class
    A NAPOT physical-memory-protection region does not cover its upper half. Issue #329 · Awaiting response
  • PrivilegeFlute
    Supervisor code can execute instructions from a user page. Issue #48 · Awaiting response
  • HangFlute
    A branch-predictor entry trained in user mode sends a machine-mode fetch into the UART range and hangs the core. Issue #62 · Awaiting response
  • HangOcelot
    Vector divide and square root at 64-bit element width never complete and hang the hart. Issue #35 · Awaiting response
